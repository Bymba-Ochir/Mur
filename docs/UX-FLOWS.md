# Хэрэглэгчийн урсгал

| Урсгал | Дараалал | Шалгах нөхцөл |
|---|---|---|
| Алдсан/олдсон | Жагсаалт → detail → холбоо/харсан мэдээлэл | Guest, эзэмшигч, өөр хэрэглэгч |
| Зар нийтлэх | Нэвтрэх → form → зураг → validation → хадгалах | Failure draft, duplicate submit |
| Үрчлүүлэлт | Жагсаалт → detail → хүсэлт → эзэмшигчийн шийдвэр | Applicant/owner эрх |
| Асрах | Жагсаалт → detail → огноо → хүсэлт → шийдвэр/үнэлгээ | Давхцал, үнэ, зөв төлөв |
| Messages | Conversation → message → read state | Зөвхөн оролцогч |
| My Pets | Амьтан → эрүүл мэнд → reminder | Зөвхөн эзэмшигч |
| Clinics | Filter/map → утас/page → цагийн хүсэлт | Хүсэлт нь эмнэлгээр батлагдсан цаг биш |
| Profile/settings | Profile → edit → preferences/export/delete | Хувийн мэдээлэл, account солих |
| Admin | Dashboard → moderation → audit | Server/database admin эрх |

Form бүр hint, validation, loading, error/retry, disabled төлөвтэй эсэхийг шалга. Modal Esc/X, focus, scroll lock, mobile keyboard-ийг бодит browser дээр туршина. Indigo/Coral/Sky palette-г хадгалж нэг feature-д зориулж бүх загварыг солихгүй.

## Алдсан, олдсон амьтны туршилт

Эхний долоо хоногт Баянзүрх дүүргийг санал болгож байна. Өөр дүүргийн идэвхтэй бүлэгтэй холбогдох боломжтой бол тухайн дүүргийг сонгоод SQL дэх нэрийг тааруулна. Бүлгийн админтай тохироод зарын холбоосыг бодит хэрэгцээтэй хүмүүст танилцуулна.

### Утсаар таван хүнтэй хийх туршилт

Боломжтой бол урьд нь МӨР ашиглаж байгаагүй таван хүн сонгоно. Чиглүүлэх зааваргүйгээр дараах даалгавруудыг хийлгэнэ. Тусдаа Supabase-тэй туршилтын deployment бэлэн бол оролцогчид утсаараа орно. Локал хувилбарыг ашиглах бол тухайн компьютерийн browser дээр утасны дэлгэцийн хэмжээг сонгоно. Нийтлэх, харсан мэдээлэл илгээх даалгаварт зохиомол мэдээлэл ашиглана. Хоёр тусдаа туршилтын бүртгэлээр зарын эзэн, харсан хүний үйлдлийг шалгана.

1. Амьтнаа алдсан гэж төсөөлөөд зураг, өнгө, байршил, туршилтын дугаар оруулж зар нийтэл. Нийтэлсний дараа зараа нээ.
2. Амьтан олсон гэж төсөөлөөд тохирох зар оруулах хэсгийг ол. Баянзүрх дүүргийн алдсан нохойн зарыг хайж, туршилтын зарын дэлгэрэнгүйг нээ.
3. Зарын холбоосыг хуулж, өөр цонхонд нээ. Зураг, төлөв, дүүрэг зөв танигдаж байгаа эсэхийг хэл.
4. Зарыг өөр туршилтын бүртгэлээс нээгээд хаана харснаа илгээ. Эзний бүртгэлээр зарыг дахин нээгээд харсан мэдээлэл харагдаж буйг шалга.

Эхлэх мөчийг даалгавар өгсөн цагаар, дуусах мөчийг заасан үр дүн харагдсан цагаар тэмдэглэ. Зар нийтэлж дуусгасан хувь нь тусламжгүй дуусгасан хүний тоог даалгаврыг эхэлсэн хүний тоонд хуваасантай тэнцэнэ. Тусламжтай дуусгасан тоог тусад нь бүртгэ. Тэмдэглэлд оролцогчийн нэр, утас, зураг оруулах шаардлагагүй. Хоёр ба түүнээс олон хүн ижил алхамд гацвал дараагийн засварт тэр алхмыг түрүүлж оруул.

### Бодит зарын холбоос ба долоо хоногийн дүн

- Шинэ хувилбар нийтлэгдсэний дараа зурагтай, хуваалцах зөвшөөрөлтэй бодит зар сонго. Facebook-ийн [Sharing Debugger](https://developers.facebook.com/tools/debug/) дээр линкийг шалгаж, зураг, төлөв, дүүрэг зөв гарч буйг хар. Дараа нь Messenger-ийн хувийн чатад холбоосын картыг утсан дээр шалга.
- Бүлэгт танилцуулах мессежийн загвар

  > Сайн байна уу. Баянзүрх дүүрэгт алдсан, олдсон амьтны зарыг нэг дор хайж, харсан мэдээллээ эзэнд нь дамжуулах МӨР-ийг туршиж байна. Зар хайх, мэдээлэх бол https://mur-chi.vercel.app/ хаягаар орж болно. Хэрэглэхэд гацсан зүйл байвал дээд цэсний «Санал хүсэлт»-ээр хэлээрэй.

- Долоо хоногийн дараа [зөвхөн унших SQL](../audits/lost-found-pilot-readonly.sql)-ийн дүүрэг болон хугацааг шалгаад Supabase SQL Editor дээр гараар ажиллуул. Шинэ алдсан болон олдсон зар, тэдгээрт ирсэн харсан мэдээлэл, олдсон гэж тэмдэглэсэн зарын тоог авна. `resolved` нь тухайн зарын одоогийн төлөвийг илэрхийлдэг тул дахин нэгдсэн үйл явдлын огноог энэ тооноос дүгнэх боломжгүй.
- Бөглөлтийн хувийг таван хүний ажиглалтын хүснэгтээс гаргана. SQL нь нийтлэгдсэн заруудыг тоолдог тул орхисон маягтын тоог агуулдаггүй. Vercel Hobby дээр [тусгай хэмжилтийн эвент](https://vercel.com/docs/analytics/limits-and-pricing) дэмжигддэггүй.
